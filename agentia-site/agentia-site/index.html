How a query becomes a report

One question, orchestrated across three agents.

backend/workflow.py runs the pipeline in order and checks Redis first — so the same question twice never pays for a third agent call.

01

Plan

PlannerAgent · Groq

Reads your question and breaks it into 3–5 focused subtopics worth researching separately, so nothing important gets missed and nothing gets searched twice.

02

Gather

ExecutorAgent · Tavily + Groq

Searches the live web for each subtopic and summarizes what it finds, attaching a source to every claim before it ever reaches the report.

03

Synthesize

SynthesizerAgent · Groq

Merges every finding into one markdown report with a proper sources section — readable on its own, traceable back to the web.

Behind every page

A persistent scene, an active pipeline.

The three nodes drifting behind this page aren't decoration — they're the same Plan → Gather → Synthesize sequence your query runs through, rendered once and carried across all six pages of the app: Home, Dashboard, Research, Library, Profile, and the report view.

  • Planner

    Decomposes the question. Fast, cheap, first.

  • Executor

  • Synthesizer

The platform around the agents

Everything a research tool needs to be trusted with your work.

Cited, not just answered

Every report closes with a sources section built by the Executor as it searches — no claims without a link back to where they came from.

Repeat queries return instantly

Identical questions are served straight from Redis instead of re-running the pipeline — same report, a fraction of the wait.

Sign-out that actually signs out

JWT auth with a Redis blacklist on the token's jti, so logging out invalidates the token server-side instead of just clearing local storage.

A library, not a history log

Every report is saved to MongoDB automatically and can be bookmarked, so past research stays findable instead of scrolling off screen.

Watch the pipeline, not a spinner

The Research page animates Plan → Gather → Synthesize live, so a 20–30 second run feels like progress, not a frozen screen.

Locked-down CORS by default

The API only answers to the origins listed in CORS_ORIGINS — nothing is left wide open once you deploy off localhost.
